# 📊 Wiki Trends — AI Agent Skill для продуктових рішень у B2C

> **Автономна навичка у відкритому стандарті [Agent Skills](https://agentskills.io/specification)**, яка дозволяє AI-агентам досліджувати динаміку інтересу аудиторії за даними переглядів Wikipedia, будувати візуалізації, розраховувати надійність трендів та генерувати односторінкові PDF-звіти для засновників B2C-продуктів.

---

## 💡 1. Концепція та бізнес-контекст

Перед командами B2C-продуктів регулярно постають стратегічні питання:
- *Яку тему обрати для наступного курсу або контентного модуля?*
- *Якою мовою локалізувати застосунок у першу чергу?*
- *Чи дійсно спостережуваний інтерес до ніші є стійким органічним трендом, чи це лише короткочасний сплеск або сезонність?*

Wikipedia — одне з найбільш об'єктивних відкритих джерел інформаційного попиту: сотні мільйонів користувачів шукають знання різними мовами. Проте самі по собі «сирі» перегляди сторінок не дають готової відповіді:
1. Назви статей різняться між мовами і потребують крос-мовного резолвінгу.
2. Сезонні коливання (наприклад, шкільний вересень або новорічні резолюції) можна хибно сприйняти за довгостроковий тренд.
3. Перегляди статей відображають **інформаційний попит**, а не пряму готовність платити.

**Ця навичка перетворює AI-агента на повноцінного продуктового аналітика**, надаючи йому надійні детерміновані інструменти обробки даних, алгоритми виявлення аномалій та правила верифікації гіпотез.

## 🏗️ 2. Архітектура та принцип роботи

Навичка побудована за принципом **Progressive Disclosure** стандарту `Agent Skills`:
1. **Discovery (~100 токенів):** Агент зчитує лише `name` та `description` у YAML-метаданих `SKILL.md`.
2. **Activation (<5000 токенів):** При відповідності запиту підвантажується покроковий `Workflow`, список скриптів та правила валідації.
3. **Execution on Demand:** Детальні довідники з `references/` підвантажуються агентом лише у випадку помилок або специфічних крайових випадків.

```mermaid
flowchart TD
    User["Запит користувача (B2C Founder)"] --> Agent["AI-агент (наприклад, Claude Haiku 4.5)"]
    Agent -->|1. Пошук статей за темою| S1["scripts/resolve_articles.py"]
    S1 -->|MediaWiki + Wikidata API| S1
    S1 -->|JSON маппінг мов| Agent

    Agent -->|2. Завантаження time-series| S2["scripts/fetch_pageviews.py"]
    S2 -->|Wikimedia Analytics API| S2
    S2 -->|JSON з переглядами| Agent

    Agent -->|3. Математичний аналіз| S3["scripts/analyze_trends.py"]
    S3 -->|Тренд, R², YoY, аномалії, сезонність| Agent

    Agent -->|4. Візуалізація| S4["scripts/generate_chart.py"]
    S4 -->|PNG графік з лініями тренду| Agent

    Agent -->|5. Підсумковий звіт (опціонально)| S5["scripts/generate_report.py"]
    S5 -->|PDF A4 на 1 сторінку| Agent

    Agent --> Final["Фінальна структурована відповідь + Артефакти"]
```

### Структура директорії

```text
wiki-trends/
├── SKILL.md                    # Головна інструкція для агента (YAML + Workflow + Gotchas)
├── scripts/                    # Виконувані Python-скрипти з PEP 723 inline dependencies
│   ├── resolve_articles.py     # Крос-мовний резолвінг статей (MediaWiki + Wikidata sitelinks)
│   ├── fetch_pageviews.py      # Вибірка помісячних/щоденних даних з Wikimedia REST API
│   ├── analyze_trends.py       # Регресія, розрахунок R², YoY, детекція сплесків та сезонності
│   ├── generate_chart.py       # Побудова мульти-лінійних графіків (matplotlib Agg)
│   └── generate_report.py      # Генерація односторінкового PDF-звіту (fpdf2)
├── references/                 # Довідкові матеріали для поглибленого контексту
│   ├── WIKIMEDIA_API.md         # Специфікація API, квоти, заголовки, коди помилок
│   └── ANALYSIS_GUIDE.md       # Методологія інтерпретації R², сезонності та конверсії
├── assets/
│   └── fonts/                  # Локальні Unicode-шрифти (DejaVu Sans) для кирилиці/діакритики
├── eval/
│   └── simulate_agent.py       # E2E-тестовий стенд для перевірки навичок моделлю Claude Haiku 4.5
└── README.md                   # Документація проєкту
```

## ⚙️ 3. Опис інструментів (скриптів)

Усі скрипти є **повністю автономними** завдяки стандарту [PEP 723](https://peps.python.org/pep-0723/) (inline script dependencies). Вони виконуються через `uv run scripts/<script_name>.py` без потреби створювати `virtualenv` чи вручну встановлювати пакети.

| Скрипт | Призначення | Ключові параметри | Вихідні дані |
|---|---|---|---|
| `resolve_articles.py` | Знаходить точні назви статей цільовими мовами через MediaWiki `langlinks` та Wikidata `sitelinks`. | `--query`, `--source-lang`, `--target-langs` | JSON з мапінгом `{lang: {title, project}}` та списком `not_found` |
| `fetch_pageviews.py` | Завантажує помісячну або щоденну статистику переглядів з фільтрацією ботів (`agent=user`). | `--project`, `--article`, `--start`, `--end`, `--granularity` | JSON з масивом часового ряду та сумарними переглядами |
| `analyze_trends.py` | Рахує лінійну регресію, зміну у %, YoY, Z-score аномалії, сезонність і рівень довіри (`confidence`). | `--input` (один або кілька JSON), `--output` | JSON з метриками, порівняльним аналізом та обмеженнями |
| `generate_chart.py` | Створює чистий графік у PNG (150 DPI) із лініями тренду та форматуванням чисел. | `--input`, `--title`, `--output`, `--trend-line` | PNG файл |
| `generate_report.py` | Формує стислий односторінковий PDF з графіком, таблицею метрик, висновками та обмеженнями. | `--analysis`, `--chart`, `--title`, `--output` | PDF файл на 1 сторінку |

## 🎯 4. Розбір кейсів та перевірка висновків

### Кейс 1: Інтервальне голодування (Польська vs Чеська Wikipedia)
> *«Порівняй зростання інтересу до інтервального голодування в польськомовній та чеськомовній Wikipedia за останні два роки.»*

- **Результат виконання навички:**
  - Чеська Wikipedia: стаття `Přerušovaný_půst` успішно знайдена, середньомісячний трафік ~800 переглядів. Спостерігається спадний тренд після піку 2023 року (-59% YoY).
  - Польська Wikipedia: виявлено, що окремої статті про «Post przerywany» **не існує** (є лише «червоне посилання» у статті про інсулінорезистентність).
- **Продуктовий висновок:** Спроба орієнтуватись на Польщу за цим прямим запитом виявляє значний **content gap** або незрілість термінології у польськомовному розділі. Чеський ринок має сформовану термінологію, але переживає спад після первинного хайпу.

### Кейс 2: Курс з астрономії для освітнього застосунку
> *«Ми думаємо додати курс з астрономії до освітнього застосунку. Чи зростає інтерес до цієї теми в україномовній Wikipedia, і наскільки цьому зростанню можна довіряти?»*

- **Результат виконання навички:**
  - Сумарні перегляди за 2 роки: >90 000.
  - Лінійний тренд: помірно спадний (-30% за 2 роки, $R^2 = 0.02$).
  - **Аномалії та сезонність:** чіткі екстремальні сплески у вересні кожного року (Z-score > 3.3, вересень 2022: 10 494 перегляди; вересень 2023: 9 857 переглядів проти середнього 2 768). Влітку (червень-серпень) трафік падає втричі.
- **Продуктовий висновок:** Сплеск інтересу у вересні зумовлений **шкільною програмою**, а не органічним комерційним попитом. Вкладати кошти в постійний курс високого чека ризиковано; доцільніше запустити сезонний навчальний інтенсив під початок навчального року.

## 🧪 5. Валідація на швидкій недорогій моделі (Claude Haiku 4.5)

Однією з ключових вимог завдання є стабільна робота на швидких і недорогих моделях (Claude Haiku 4.5) з підтримкою Function/Tool Calling.

### Чому навичка ідеально підходить для дешевих моделей:
1. **Код рахує, LLM інтерпретує:** Haiku не витрачає токени і не робить помилок в обчисленні відсотків, регресії чи Z-score — це робить `numpy` в `analyze_trends.py`.
2. **Єдиний інтерфейс обміну:** Усі скрипти приймають аргументи CLI і віддають валідний JSON у `stdout`, а діагностику пишуть у `stderr`.
3. **Самокорекція агента:** Якщо аргументи неповні або файл не знайдено, скрипти повертають зрозумілі підказки (self-explanatory error messages).

### Реальний E2E тест через OpenRouter:
У директорії `eval/` розміщено автономний раннер `simulate_agent.py`, який ініціалізує модель `anthropic/claude-haiku-4.5`, передає їй системні інструкції з `SKILL.md` та інструмент виконання bash-команд.

**Фрагмент живого логу виконання:**
```text
[AGENT] uv run scripts/resolve_articles.py --query "астрономія" --source-lang uk --target-langs uk
-> Знайдено статтю: "Астрономія" (uk.wikipedia.org)

[AGENT] uv run scripts/fetch_pageviews.py --project uk.wikipedia.org --article "Астрономія" --start 20230101 --end 20250101 --granularity monthly --output astronomy_uk.json
-> Завантажено 25 часових точок, збережено в astronomy_uk.json

[AGENT] uv run scripts/analyze_trends.py --input astronomy_uk.json --output analysis_astronomy.json
-> Розраховано: direction="declining", R²=0.10, вересневі сплески Z=3.94

[AGENT] uv run scripts/generate_chart.py --input astronomy_uk.json --title "Тренди 'Астрономія' (uk.wikipedia.org)" --output astronomy_chart.png --trend-line
-> Графік побудовано: astronomy_chart.png

[AGENT] Синтезує відповідь: 
"Інтерес падає (-53% за період). Надійність висновку середня (R²=0.10). 
Виявлено вересневу академічну сезонність (шкільна програма). 
Рекомендація: бути обережним з інвестиціями в курс..."
```

## 🚀 6. Швидкий старт

### 1. Передумови
Потрібен Python 3.10+ та менеджер пакетів `uv`:
```bash
# Встановлення uv (якщо ще не встановлено)
curl -LsSf https://astral.sh/uv/install.sh | sh
```

### 2. Клонування та перевірка навички
```bash
git clone <URL_РЕПОЗИТОРІЮ>
cd wiki-trends

# 1. Знайти статті цільовими мовами
uv run scripts/resolve_articles.py --query "Language education" --source-lang en --target-langs uk,pl,de

# 2. Завантажити дані
uv run scripts/fetch_pageviews.py --project uk.wikipedia.org --article "Вивчення_іноземних_мов" --start 20230101 --end 20241231 --output uk_views.json

# 3. Проаналізувати тренди
uv run scripts/analyze_trends.py --input uk_views.json --output analysis.json

# 4. Згенерувати графік та PDF
uv run scripts/generate_chart.py --input uk_views.json --output chart.png --trend-line
uv run scripts/generate_report.py --analysis analysis.json --chart chart.png --title "Звіт: Вивчення мов в Україні" --output report.pdf
```

## 📈 7. Ітеративний розвиток та масштабування

Як розвивати навичку далі для роботи зі складнішими дослідженнями та більшими обсягами даних:

1. **Нормалізація на обсяг мовного розділу (Population/Traffic Normalization):**
   - 10 000 переглядів в англійській Вікіпедії та 10 000 в українській мають принципово різну вагу.
   - *Розвиток:* Інтеграція ендпоінту `/metrics/pageviews/aggregate/{project}` для ділення переглядів статті на загальний трафік розділу (Share of Voice).

2. **Крос-валідація джерел (Multi-Source Triangulation):**
   - Додавання коннекторів до Google Trends API (пошуковий намір), Reddit API (дискусійна активність) та HackerNews/ProductHunt (ранній tech-хайп).

3. **Кешування та автономний локальний банк даних:**
   - Впровадження локального SQLite-кешу (WAL mode) для збереження часових рядів, щоб уникати повторних викликів Wikimedia API при уточнюючих запитах.

4. **Прогнозування та статистичне моделювання:**
   - Заміна простої регресії на Prophet або сезонну декомпозицію (STL / ARIMA) для короткострокового прогнозування трафіку на наступні 6-12 місяців із довірчими інтервалами.

5. **Тематичні кластери та категорії (Category-Level Aggregation):**
   - Автоматичний збір переглядів не по одній статті, а по всьому піддереву категорій Вікіпедії (наприклад, категорія «Здорове харчування» з усіма 40 спорідненими статтями).
